# Native editor boundary editing

`NoteBlocksEditor` is shared by compact Chat, fullscreen Chat, Add Note and Edit Note. It uses React Native 0.86 `TextInput`, not WebView/contenteditable or a third-party rich editor. Plain paragraphs share a text run; list items are separate text blocks with `{ kind, id, checked? }` metadata. Images are separate blocks referencing existing/staged attachments. `content_json` persists structure and completion; plain notes keep their existing text storage. No schema migration is involved.

## Reproduction and cause

Before the change, executing the existing Backspace callback with a nonempty numbered, bullet, checklist or plain block at offset zero produced zero structural commits. The handler only recognized empty formatted blocks. Native deletion cannot cross distinct TextInputs. The plain/rich render branches also changed the input's ancestor tree, and normalization could replace the focused key with a preceding block's key. Structural cursor restoration used a deferred animation frame that could race a later edit.

The fix keeps one ancestor tree and preserves the active input's key during formatting and normalization. Structural operations use `liveBlocks` synchronously, record existing session history, and restore only structural selections in a layout effect. Ordinary typing leaves cursor, character/range deletion, grapheme handling, autocorrect and IME composition with the native input. Transfers of focus between the editor's inputs do not report a blur of the whole composer.

## Editing rules

- At a list/checklist item's beginning, Backspace removes that item's formatting and preserves its words. The next delete joins the preceding paragraph/item. A merge inherits the preceding item's list/completion metadata. If the following paragraph contains several lines, only its first line joins the preceding list item.
- Removing formatting beside plain text preserves the paragraph separator inside the combined native input. The next native Backspace deletes that separator. The active key survives this normalization.
- Enter splits a nonempty item and continues its list; new checklist items start unchecked. Enter on an empty item exits the list. Existing multiline-paste behavior is retained (pasted checklist paragraphs remain plain).
- At a plain block boundary, merge with the preceding text, preserving order and placing the caret at the join. The implicit block separator is consumed; authored newlines inside either run remain intact.
- Across an inline image, move to the preceding text slot. Backspace does not delete image files or image blocks; use the image's Remove action.
- Undo/redo uses the existing session history for both document and cursor. External document/image changes reset obsolete snapshots.

`note-lists.ts` owns formatting, split/Enter, remove-format, merge and boundary-cursor operations. `note-content.ts` continues to own image insertion/removal and ordinary text updates. All screens use those same operations through the shared component.

## Keyboard delivery

React Native's Android InputConnection wrapper reports soft-keyboard boundary deletes even when no text changes. A deferred fallback acts only if no text change, selection move or intervening structural edit invalidated its captured block. The existing scoped native input registration additionally handles Android hardware DEL at a collapsed offset zero. UIKit's scoped `deleteBackward` override reports the equivalent operation when no marked composition is active. Other native deletes and paste actions retain their original handlers. Native Backspace events are filtered out of image-paste subscribers.

Native module changes require rebuilding the development/release binaries. JavaScript refresh alone does not install the hardware/iOS hooks.

`normalizeClearedDocument` now runs only during structural Backspace or Enter exiting an empty list item. If no list, image, word or authored space remains, it collapses newline-only plain runs into one empty paragraph using the focused block's existing key and cursor zero. Deleting an item's last character still retains its list/checklist formatting. Other deliberately empty tasks, whitespace authored during ordinary typing, and media prevent cleanup. Passive rendering, ordinary `onChangeText` and IME composition do not invoke the cleanup.

The shared editor recognizes the canonical empty paragraph and cancels obsolete pending row scrolling, drops old row coordinates and resets its ScrollView to offset zero without animation. Native viewport/content-size changes repeat that guarded scroll reset only while the document is still empty. A late layout event after typing resumes cannot reset the viewport. ## Persistent Android alignment follow-up (2026-10-18)

The reported centered `Message note...` placeholder was reproduced in the actual `FullscreenComposer` modal on the connected Samsung SM-S911B (Android 16). The previous standalone empty-layout fixture did not supply `textAlignVertical` in its rich-input style, so it missed the production-only prop/style collision. The earlier blank-document and scroll fixes do not address native alignment resets.

The rendered Chat path is Modal → SafeAreaProvider → SafeAreaView → AppHeader + KeyboardAvoidingView → NoteBlocksEditor ScrollView → content View → text row → list body → BlockInput/TextInput, followed by the toolbar and footer. React Native flattens some Views in the native hierarchy. Add Note places the same editor inside its fullscreen SafeAreaView/KeyboardAvoidingView. There is no WebView, contenteditable, or separately positioned placeholder. The fullscreen `flex`/`flexGrow` wrappers size the writing area; the Android EditText's vertical gravity controls its text and native hint within that area.

`BlockInput` previously supplied a constant `textAlignVertical="top"` prop, while fullscreen rich-input styles also supplied `textAlignVertical: 'top'`. Returning to the plain-input style removes the style key. Executing this checkout's actual React Native 0.86.3 `ReactNativeAttributePayload.diff` yields `textAlignVertical: null` for that transition: the unchanged prop does not restore the deleted style value. Android's `setTextAlignVertical(null)` restores default gravity. The large empty input then shows its native placeholder in the center. The first unexpected value is this native update payload, rather than a retained blank block or a changed scroll coordinate.

The fix destructures compact Chat's optional alignment out of the extra props and supplies alignment only as the final style entry. The rich → plain native payload now retains `'top'`; compact Chat's explicit center/top behavior still works. This is one shared change for Chat, Add Note, and Card Edit Note. No padding, flex sizing, timers, focus calls, remounts, document normalization, or storage code changed in this follow-up.

## Limits and remaining coverage

Native selection is confined to one TextInput. A continuous selection across different list items or across an image is not supported by this architecture; formatting multiple selected plain paragraphs can also collapse the selection into the first resulting native item. This change does not claim cross-block selection support or a document-wide native undo stack. Session toolbar undo/redo remains available.

Gboard is not installed on the connected Samsung device. Gboard, SwiftKey, a physical iPhone/iPad keyboard, and physical iOS autocorrect/composition still require manual acceptance. The 5,000-item test verifies document updates and object preservation, not interactive frame time. A full long-document typing/scroll performance profile remains a device QA task.
